## 本轮修复

- Windows 扩展路径保留用于文件边界检查，传给 Node 时转换为常规路径。
- 就绪检查只读取本次启动地址，并处理官方 303 / Cookie 认证握手。
- 开发服务器排除运行时与测试数据监听，避免 Windows 恢复目录被监听器锁定。
- TUN 网络的已知发行域名支持 `198.18.*` 虚拟 DNS，任意私网地址仍然拒绝。
- 导入使用本次创建的精确实例 ID，避免并发创建时污染其他实例。
- 损坏的插件库存只报告在对应实例中，保留其他实例与恢复操作。
- 内核有备份引用时禁止注销；外部内核版本、CLI、锁文件变更时拒绝继续执行。
- 展示与导出的诊断日志隐藏令牌；启动链接仅用于打开本机认证服务。

## 需要用户继续验收

以下项目没有以源码存在或静态检查代替真实验证：

1. 在目标 Windows 机器运行安装器，检查安装路径、快捷方式、升级和卸载。
2. 下载并安装 EAC Full / Lite 大型便携包，再启动其原生桌面窗口。
3. 下载并手动安装官方 Desktop，登记其已安装 EXE，检查启动与退出。
4. 原有原生桌面端自带全局单实例策略；确认其实际数据目录行为。
   真正的多内核并行使用 Harness 实例，不假定旧桌面二进制已支持多开。
5. 各社区插件的完整业务、真实模型请求、EAC 私桥组件和大型 EAC-Pack 全套业务。
6. macOS、Linux、不同 WebView2 版本、低资源设备与长期运行。
7. 中断网络、低磁盘空间与数 GB 级归档的长时间恢复场景。
8. 重新开放 GitHub 登录时：注册 OAuth App 并启用 Device Flow，构建时设置
   `EAC_GITHUB_CLIENT_ID` 烧入程序，两个 `LOGIN_ENABLED` 开关置回 `true`，并做一次
   真实设备流授权与一次对真实仓库的 Star / 取消 Star（本轮为避免改动账号未执行
   外部写入）。
9. 将新版 `pack-hall/server.mjs` 部署到公网大厅后，确认所有客户端显示
    `大厅实时` 榜单；旧大厅会自动回退到 `本机记录`。
10. 从插件市场实际安装一个插件，确认安装成功后的下载计数进入日/周/月榜。

## 使用边界

- 核心启动、安装、恢复均为真实操作；下载当前没有断点续传。
- 导出描述文件不含会话、密钥和机器路径。无法保留不可变来源的归档/Git 插件
  会明确拒绝描述导出；完整实例数据使用备份恢复。
- 新版本不会自动覆盖旧内核或迁移其他实例。未知兼容性不会显示成“已兼容”。
- Windows 预览安装包未做发布者签名；正式发行仍需目标平台验收和签名。

## 本地检查命令

```powershell
npm run build
npm run test:backend
npm run dev:connected
```

`EAC_LAUNCHER_HOME`；网络安装验收脚本为 `scripts/verify-connected.mjs`。
本次安装包及其校验值放在 `artifacts/`，该目录已忽略，不会混入源码提交。
